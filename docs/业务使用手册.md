# IR 供应链控制塔 · 业务使用手册

这份手册给计划员、值班负责人和只读管理层。它说明每天怎么用控制塔，以及这套系统相对「分别登录十一个执行系统」多出来的能力。想先看图，从 [图文导读](./图文导读.md) 开始。

技术对接、接口和表结构见 [供应链大脑构造](./供应链大脑构造.md) 与 README。

浏览器打开控制塔后，默认进入「控制塔总览」。演示账号 `admin / admin123`，登录后请立刻改密码（右上角姓名 → 修改密码，至少 6 位）。

## 1. 项目亮点

控制塔自己不接单、不拣货、不算账。订单仍在 OMS，库存仍在 WMS，运单仍在 TMS，钱仍在 BMS。它的价值是把这些系统收成一张可执行的指挥面。

1. **一屏指挥，不用来回切系统。** 总览同时给出目标达成、未达标项、待审批决策、待执行指令、资金结论和下一步动作。点「执行」就把指令打到对应系统，不必再打开 OMS、WMS 或 TMS。一次最多批量处理 8 条；「执行高等级」只处理当前列表里的高等级事项。
2. **成本与效率可以当场换立场。** 总览上的滑块决定控制塔更省钱还是更快。成本侧重会倾向挂起卡单、换更便宜的承运商、加大采购批量；效率侧重会倾向自动过审、追更快运力、仓内补货。保存后会重评预警，并作废与新立场冲突的待办，避免两套建议叠在一起。
3. **两套沙盘，一套给人手推，一套给系统推荐。** 人工沙盘用来改需求倍率、分仓、承运和资金盘，看完再决定「生成指令」还是「立即执行」。系统自动沙盘按当前立场在多套方案里打综合分，默认只生成待办，不自动下发。
4. **资金盘按量级推演，而不只看一张演示账。** 人工沙盘可以选 10 万、百万、千万、亿、十亿，也可以填自定义金额。系统用当前快照跑常态、2 倍和 5 倍需求，给出可靠、偏紧或不足，并标出最低可靠资金。「自动跑完所有档位」用来检查这些量级下全流程有没有断。零件规模按最多 10 万 SKU、单 SKU 库存最多千万级来设计。
5. **自动平衡带护栏，不是无约束自动下单。** 运行模式可以关、只给建议，或自动执行。自动执行只放行低风险且在护栏内的决策：单次执行有上限、采购金额有上限、同类动作有冷却，服务水平掉下去之后不再自动做降本。其余进入待审批，由计划员批准或拒绝。
6. **一张订单看完整条履约链。** 订单追踪把 OMS 订单、WMS 出库和 TMS 运单拼在一起，并带上该单成本、相关预警和已下指令。可以按卡滞、加急、仓库和订单状态筛选。
7. **指令跨十一套执行系统，而且重复点击不会连发两次。** 挂起、改仓、分配、补货、调度、换承运商、采购建议、催单、释放生产订单、工程变更、开票、商机推进、工单升级、经销商补货、审批待办，都从「联动指令」或总览的下一步动作出去。同一条指令带幂等键，对方已经执行过就返回第一次的结果。BMS 只提供成本，控制塔不改结算账。
8. **建议和实账分开。** 成本页的节约来自已成功指令上的预计节约，换承运商按运价差估算。已经进入 BMS 的运费优先用结算数。页面上的节约不是财务已经入账的利润。

## 2. 谁能做什么

| 角色 | 能做的事 |
| --- | --- |
| 管理员 | 全部写操作，外加用户管理和操作日志 |
| 计划员 | 改立场、执行指令、跑沙盘、批平衡决策、改规则和目标。不能管用户 |
| 只读用户 | 看全部页面。执行、保存、生成指令这些按钮不出现 |

执行系统里的单据状态以各系统为准。控制塔上的数字是同步过来的快照，默认同步周期 5 分钟，总览上也可以手工刷新。源系统刚改完的单，控制塔最多晚一个周期才看见。

## 3. 每天建议这样用

1. 打开「控制塔总览」，先看目标达成分和未达标个数。
2. 看资金结论是可靠、偏紧还是不足。不足时先不要采用会加大采购的沙盘方案。
3. 看「下一步动作」。高等级先处理；单条点「执行」，或一次点「执行高等级」。
4. 有待审批决策时，进「自动平衡」看依据和预期影响，再批准或拒绝。
5. 需要解释某一单时，进「订单追踪」，按订单号打开时间线。
6. 需要回答「如果需求翻倍、或者资金只有这么多」时，进「人工沙盘」或「系统自动沙盘」，先看结果，再决定是否生成待办。

只读用户停在第 1、2、5 步，把要执行的事项交给计划员。

## 4. 页面怎么用

菜单顺序就是下面的顺序。

### 控制塔总览

这是值班入口。

- **成本 / 效率策略**：滑块越靠右越偏成本。改完要点「保存并重评预警」才生效。只读用户只能看。
- **下一步动作**：来源分预警、待办指令、平衡决策、沙盘方案。资金不可靠时，采用沙盘推荐也会出现在这里。「执行高等级」一次最多 8 条。某行显示「需管理员」时，当前角色不能下发。
- **仓负荷、预警、资金盘、生态单据**：用来判断问题在哪个仓、哪类单据，不在这里改数。

### 订单追踪

按订单号、OMS 状态、仓库、卡滞、加急筛选。列表里优先级达到 10 会标「高优」。

点进详情看时间线：下单、分仓、出库、在途、签收，以及这张单上的成本、预警和指令。追踪用来解释，不用来改仓。改仓、加急、挂起回到总览或「联动指令」。

### 业务目标

预置五项目标，按权重合成达成分：

| 目标 | 预置线 |
| --- | --- |
| 单均成本 | 不高于 25 |
| OTIF | 不低于 95% |
| NPS 估算 | 不低于 50 |
| 缺货率 | 不高于 5% |
| 供应商准交率 | 不低于 92% |

状态分达标、预警、未达标。NPS 不是问卷分，是运营代理：准时且无异常算推荐，延迟超过 24 小时、异常运单、付费后取消算贬损。计划员可以改目标和权重。改权重会改变总览上的达成分，不会自动改已经发出的指令。

### 自动平衡

引擎大约每 30 分钟跑一次，也可以手工运行。策略包括库存再平衡、供应催货、延误挽回、承运成本优化、订单解阻、改仓。每条决策带依据、预期成本影响、预期服务影响和风险等级。

| 运行模式 | 含义 |
| --- | --- |
| 关闭 | 不产生新的自动决策 |
| 仅建议 | 决策进入待审批，不自动执行 |
| 自动执行 | 只执行低风险且过护栏的决策，其余仍待审批 |

护栏在「护栏配置」里：定时表达式、单次上限、采购金额上限、服务护栏达成率。OTIF 或 NPS 低于服务护栏时，降本类动作不再自动执行。

批准前先看运行详情里的运行前 / 运行后。拒绝可以填原因。拒绝不会去执行系统改单。

### 供应协同

看采购订单、ASN、供应商准交，以及 SAP 库存和 WMS 库存是否对得上。在途按 SKU 加仓库计入补货，上海的在途不会盖住北京的缺口。这里发现延误或低库存后，到「补货建议」或「联动指令」生成采购建议、催单或仓内补货。

### 预警中心

预警来自规则，等级分高、中、低，状态分待处理、已确认、已解决、已忽略。

- **执行**：按该预警的建议动作下发。建议里的动作要全部成功，预警才变成已解决；有一条失败就保持待处理，可以再点。
- **确认 / 忽略**：表示人已经看过，不代表执行系统已经改完。

条件消失后，已解决的预警可以在下一轮重新打开。停用规则不会自动关掉已经打开的预警。

### 规则管理

规则决定什么情况算预警、建议做什么。类型包括订单卡单、仓库卡单、运输延误、待调度、低库存、成本超支、预测缺货、ASN 延误、供应商风险、ERP 低库存、生产订单待释放，以及外部单据状态。

计划员可以增删改和启停。改规则后要等下一轮评估，或在总览保存立场时触发重评，新条件才会反映到预警列表。

### 联动指令

所有跨系统动作的台账。状态：

| 状态 | 含义 |
| --- | --- |
| 待执行 | 已生成，还没打到执行系统 |
| 执行中 | 正在下发 |
| 成功 | 执行系统已接受 |
| 失败 | 被拒绝或调用失败，可以重试。重试是一张新指令 |
| 待对账 | 调用超时或结果不明。不要立刻再发同一动作，先到执行系统核对 |
| 已重试 | 旧指令已被新指令接替 |
| 已作废 | 立场变化后被取消的待办，没有下发 |

常用动作和注意点：

- **挂起订单**只适用于已创建、已审核。已支付及之后的卡单用「订单加急」，不要挂起。解除挂起会回到已创建，不会回到挂起前的已支付或已分配。
- **仓内补货**在源仓和目标仓不同时，实际走跨仓调拨。
- **更换承运商**改的是运单。页面上的节约是运价差，不是 BMS 已经重算的账单。
- **采购建议、ERP 建申请、经销商补货**会在控制塔记下对应在途，避免同一缺口重复采购。
- **发起审批、工程变更、开票、商机、工单**在没有 API Key 的登录模式下发不出去，需要管理员在「系统集成」里配好 Key。

### 需求预测

按 SKU 看未来需求。方法有 7 日移动平均、指数平滑、霍尔特、按星期的季节朴素，以及自动选择。自动选择用最近 14 天的回测误差挑一个误差最小的方法。预测结果给补货和沙盘用，不直接改执行系统库存。

### 补货建议

对照可用库存、在途和安全库存，给出该补多少。一行可以转成采购建议或仓内补货指令。转成指令后到「联动指令」执行，或在总览的下一步动作里执行。

安全天数和补货提前期跟总览上的立场一起显示。库存够时，系统更倾向短交期而不是盲目加高安全库存。

### 人工沙盘

用来回答「如果需求变成现在的 2 倍、只从一个仓发、资金只有这些，成本和缺货会怎样」。

1. 新建场景，设定需求倍率、分仓策略（就近、最低成本、平衡、单仓）、承运、成本权重、效率权重、资金盘。
2. 运行后看成本、服务水平、缺货和按日、按 SKU 的结果。
3. **生成指令**只写入待执行，不立刻改执行系统。**立即执行**会马上下发。每类动作最多 8 条，避免一次改掉全部在途单。
4. **资金盘推演**用当前快照看这笔钱是否可靠，并给出推荐方案。占用低于 80% 且没有把采购推迟，才算可靠。
5. **自动跑完所有档位**依次跑 10 万到十亿。过万 SKU 时，系统会缩小推演范围：只补已有库存的仓库，并在资金充足时复用一次全量结果。扫描结束会说明是通过，还是有档位需要关注。

自定义金额不受这五档限制，但库存金额若按演示单价已经超过所填资金，该档会标成可能不足。

### 系统自动沙盘

系统按当前成本 / 效率立场，在一组预设方案里算综合分，标出推荐方案。默认只把推荐放进待办，不立即执行。要真下发，在总览执行对应的沙盘动作，或在人工沙盘里对已采用的场景点「立即执行」。

推荐不是永远「把安全库存降到最低」。库存充足时倾向低安全加短交期；库存紧时退回短交期补货，而不是硬降安全库存。只换便宜承运商却把服务水平拉下来的方案不会被当成推荐。

### 场景对比

把人工场景、系统自动场景和基线放在一起，比成本、效率、综合分、缺货和服务水平。用来开评审会，不直接下发。要执行，回到对应场景点生成指令或立即执行。

### 成本分析

按类型、仓库、承运商、日期看实际成本，并对照成本目标。节约金额只统计状态为成功的指令。有 BMS 运费的订单用 BMS 的数，还没结算的运单仍用 TMS 快照。负的调整额也算 BMS 已经入账，不会因为金额是负的就退回 TMS。

把这里的节约讲成「本月已落袋利润」是错的。它是控制塔的预计节约。

### 系统集成

管理员和计划员在这里看十一套执行系统是模拟还是在线、上次同步是否成功。演示环境默认全部是模拟，数据稳定、可重复。要打到真实系统，把对应系统改成在线，并填对地址。有 API Key 走开放指令；只填账号密码时，订单、仓储、采购、ERP、经销商可以走登录后的业务口，审批、工程变更、发票、CRM 仍然需要 Key。

同步失败时，总览和追踪仍显示上一次成功的快照。先看这里的错误，再判断页面上的数是不是旧的。

### 用户管理与操作日志

只有管理员能进。用户角色就是上面的管理员、计划员、只读用户。操作日志记录谁在什么时候改了立场、规则、指令和用户，用来事后核对，不能用来撤销已经下到执行系统的动作。

## 5. 使用时不要误判的事

- 控制塔改的是指令和自己的快照。执行系统拒绝时，以执行系统的报错为准，快照不会偷偷改成成功。
- 挂起不能用来处理已支付未发货的单。这类单用加急。
- 结果不明的指令先去执行系统对账，不要连续重试。
- 资金结论「可靠」只说明按当前快照和推演假设，这笔钱覆盖得住，不是资金账户的真实余额。
- 模拟模式下的成功，只说明控制塔自己的闭环通了，不代表 OMS、WMS 里真的有这张单。
