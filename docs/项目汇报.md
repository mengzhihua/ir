## 2. 为什么要做控制塔

OTWB 四套系统已经把"接单 → 出库 → 运输 → 结算"跑通了，但它们各自记账、各看各的屏，带来三个痛点：

```mermaid
flowchart LR
    A[订单卡在哪一环<br/>没人一眼看得出] --> D[控制塔]
    B[成本是 BMS 事后算出来的<br/>决策时看不到] --> D
    C[改仓 / 换承运商 / 补货<br/>靠人跨系统操作] --> D
    D --> E[全链路可视]
    D --> F[事前推演 + 事中预警]
    D --> G[跨系统一键协同]
```

目标是把"降低 BMS 核算出来的成本"变成一个可以在 **下单前推演、执行中干预、事后复盘** 的闭环。

## 3. 系统全景

![系统全景](./images/ir-landscape.png)

```mermaid
flowchart TB
    subgraph IR["IR 控制塔（:8090 / :5174）"]
        direction LR
        P[感知<br/>适配器 + 定时同步] --> M[记忆<br/>统一快照库] --> C[认知<br/>看板 / 追踪 / 成本] --> D[决策<br/>预警 / 预测 / 沙盘 / 自动平衡] --> A[行动<br/>跨系统协同指令]
        A -.执行结果回写.-> M
    end
    OMS[(OMS 订单)] <--> IR
    WMS[(WMS 仓储)] <--> IR
    TMS[(TMS 运输)] <--> IR
    BMS[(BMS 结算<br/>只读)] --> IR
    IR --> SRM[(SRM 采购)]
    IR --> SAP[(SAP)]
    IR --> ECO[(BOM / INV / DMS / CRM / OA)]
```

- **只读 BMS**：控制塔只取成本，不改账，节约值与实账分开展示。
- **MOCK / HTTP 双模式**：每套系统可单独切换，无凭据时走登录模式回退，便于分阶段接入。
- **安全边界**：出站地址校验（禁止内网/链路本地/云元数据地址）、DNS 固定、禁用重定向、指令幂等键防重发。

## 4. 核心能力与成果

### 4.1 控制塔总览 —— 一屏指挥

![控制塔总览](./images/report/dashboard.png)

- 30 日订单量 / 履约漏斗 / 30 日总成本与单均成本（与成本页同一口径）。
- **可下发的指令队列**：目标偏差、待审批、下一步动作集中在一屏，点执行即打到对应系统（一次最多 8 条）。
- 成本 / 效率立场滑块：保存后自动重评预警，并作废与新立场冲突的待办。

### 4.2 全链路追踪 —— 一张订单看完整条链

![订单追踪](./images/report/trace.png)

按订单号把 OMS 订单、WMS 出库单、TMS 运单、BMS 成本、相关预警与已下发指令拼成一条时间线，卡单直接定位到环节。

### 4.3 预警与协同指令 —— 发现即处置

![预警中心](./images/report/alert.png)

![联动指令](./images/report/action.png)

```mermaid
sequenceDiagram
    participant R as 规则引擎
    participant A as 预警中心
    participant U as 计划员
    participant X as 指令中心
    participant S as OMS / WMS / TMS / SRM / SAP
    R->>A: 定时评估规则（卡单 / 低库存 / 运单延误…）
    A->>U: 生成预警 + 建议动作
    U->>X: 一键执行 / 批量执行
    X->>S: 带幂等键下发（改仓 / 挂起 / 分配 / 补货 / 换承运商 / 建 PR…）
    S-->>X: 成功 / 失败 / 未知
    X-->>A: 回写结果，失败可重试，未知进入对账
```

- 规则可配置，覆盖订单卡滞、库存低于安全线、运单超时、SAP 低库存、OA 待办等场景。
- 指令跨 12 套系统，重复点击不会连发；结果 UNKNOWN 时进入待对账而非误判成功。

### 4.4 销量预测与补货 —— 从经验到模型

![需求预测](./images/report/forecast.png)

![补货建议](./images/report/replenish.png)

- 四种模型（移动平均 / 指数平滑 / Holt / 季节朴素）+ 自动选优，按 SKU × 仓输出 14 日预测。
- 补货建议叠加在途采购（含多行采购单逐行归属）、安全库存天数，可一键批量生成 WMS 补货 / SRM 采购建议 / SAP PR。

### 4.5 沙盘推演 —— 先算再干

![人工沙盘](./images/report/sandbox.png)

![场景对比](./images/report/compare.png)

- 可调参数：需求倍数、渠道结构、分仓策略、承运商组合与费率、安全库存、仓储 / 作业 / 包材 / 缺货成本、补货周期、初始库存。
- 输出总成本、服务水平、成本分 / 效率分 / 综合分，多场景横向对比并可一键转为指令。
- **资金盘**：按 10 万 / 百万 / 千万 / 亿 / 十亿量级一次跑完，支撑 10 万级 SKU。
- **系统自动沙盘**：定时按综合分给推荐，默认只生成待办，不越权执行。

### 4.6 目标、自动平衡与供应协同 —— 有护栏的自动化

![业务目标](./images/report/objective.png)

![自动平衡](./images/report/balance.png)

![供应协同](./images/report/supply.png)

- 业务目标（成本 / 服务水平 / 库存周转）由管理员设定，页面实时显示达成偏差。
- 自动平衡三档：关闭 / 只建议 / 仅自动执行低风险决策；服务水平跌破阈值后自动停止降本动作。
- 供应协同：SRM 采购单、ASN、SAP 未清项与在途统一展示，缺口直接生成催单 / PR。

### 4.7 成本分析 —— 与 BMS 同一口径

![成本分析](./images/report/cost.png)

按仓 / 承运商 / 成本类型拆分 30 日成本；已进入结算的运费优先用结算数，未结算部分用估算并标注。

### 4.8 系统集成与权限 —— 可运维

![系统集成](./images/report/integration.png)

![用户管理](./images/report/system-users.png)

- 每套系统独立配置地址 / 模式 / 凭据，健康检查与同步日志可视。
- 三种角色：管理员（配置与目标）、计划员（预警 / 沙盘 / 指令）、查看者（只读）；操作日志全量留痕。

## 6. 技术方案

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 后端 | Java 17 · Spring Boot 2.7 · MyBatis-Plus · H2(文件库) | 与 OTWB 同构，零外部依赖即可单机运行 |
| 前端 | Vue 3 · Vite · Element Plus · ECharts | 19 个页面，路由级权限守卫 |
| 集成 | Apache HttpClient · 适配器模式 | MOCK / HTTP 可切换；3s 连接超时；DNS 固定；禁重定向 |
| 安全 | PBKDF2 口令、Bearer Token、角色拦截器、出站地址校验、操作日志 | 生产要求 `IR_ALLOW_PRIVATE_HOSTS=false` 并修改默认密码 |
| 交付 | GitHub Actions：CI（测试 / Lint / 构建）+ Release（四平台原生包） | Docker 多阶段构建，`docker compose up -d` 一键启动 |

## 10. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 外部系统接口契约与 MOCK 不一致 | 同步失败或数据口径偏差 | 已有 HTTP 契约测试与同步日志；联调阶段逐系统开启 |
| 自动执行误操作 | 影响真实业务单据 | 自动平衡默认"只建议"，低风险白名单 + 服务水平护栏 + 幂等键 + 全量操作日志 |
| 单机 H2 容量与可靠性 | 大数据量下性能与备份 | 已预留 MySQL 兼容模式，下一步外置数据库 |
| 成本数据滞后（BMS 事后结算） | 决策时成本为估算 | 页面区分"估算 / 实账"，结算数到达后优先采用 |
